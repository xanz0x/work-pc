# План правок: удаление файла из библиотеки с опцией «удалить с ПК»

## Контекст
- Файлы в библиотеке = записи серверного drive.json (личные `shared:false`, лежат в папке хранения на ПК под исходным именем, `relPath`), подмешанные в UI как `cloud:*` карточки.
- Локальный сейф-объект (`D.files`) — это метаданные для индексации; демо-файлы — отдельная история.
- Удаление сейчас:
  - ПКМ → «Убрать из библиотеки» → `window.confirm` (в Electron работает как нативный confirm? — да, confirm поддерживается) → `fk.forgetKey + D.removeFile` — только из сейфа-индекса, байты на диске остаются.
  - Инспектор «Удалить из сейфа» → то же самое.
  - Общая копия удаляется через `LibraryShareDialog` (mode:remove → DELETE /ai-api/cloud/file/[cloudId]).

## Требование пользователя
При удалении файла, который физически лежит в папке хранения на ПК:
1. Диалог «Удалить с устройства?» с чекбоксом (по умолчанию ВКЛ: «Удалить также файл с ПК (из локальной папки)»).
2. Галочка ВКЛ → сервер удаляет байты из папки хранения (fs.rm по relPath внутри root, с проверкой контainment).
3. Галочка ВЫКЛ → файл остаётся в папке на ПК, удаляется только запись в библиотеке.
4. «Файл 100% должен удаляться» — после DELETE проверить отсутствие файла на диске; при неудаче — честная ошибка (не молча).

## Изменения
### Сервер
- `lib/cloud-store.ts`:
  - `deleteFileImpl(id, opts?: { removeBytes?: boolean })`: если `removeBytes` и `f.relPath` — вычислить abs внутри root (containment!), `fs.rm(abs, {force:true})`, повторить попытку при EBUSY/EPERM (Windows может держать файл) до 3 раз с паузой 150 мс; ошибка удаления → CloudError PROVIDER (запись в drive.json НЕ помечается удалённой, если байты не удалились — «100%»).
  - Если `removeBytes=false` — текущее поведение (soft-delete записи).
  - Экспортировать `deleteFile(id, opts)`.
- Маршрут `app/ai-api/cloud/file/[id]/route.ts` DELETE: прочитать `{ removeBytes }` из тела (fetch DELETE с JSON-телом — ок), передать в deleteFile.

### UI
- Новый компонент `components/library-delete-dialog.tsx`: окно «Удалить «X» из библиотеки?», чекбокс «Удалить также файл с компьютера (из папки хранения)» — ВКЛ по умолчанию, подпись с путём файла; кнопки Отмена/Удалить. Если у файла нет absPath/relPath (не в папке ПК) — чекбокс скрыт.
- `screen-library.tsx`:
  - состояние `deleteRequest: { kind:'file', id, title, cloudId?, absPath? } | null`;
  - ПКМ «Убрать из библиотеки» → открыть диалог (вместо window.confirm); после подтверждения: если cloudId и чекбокс → DELETE с removeBytes:true, затем D.removeFile; иначе — старое поведение;
  - массовое удаление (bulk) оставляем как есть (в сейф, без диска) — пользователь просил про файл из папки; НО добавить ту же опцию нельзя без усложнения — оставим.
- `library-file-inspector.tsx` кнопка «Удалить из сейфа» → тоже открывает диалог (через новый проп `onDeleteRequest(id)`).

### Проверки
- tsc, vitest.
- Живой прогон на упакованном сервере: создать файл в папке хранения (через upload API), удалить с галочкой → файл исчез с диска; без галочки → остался; запись в drive удалена в обоих случаях.
