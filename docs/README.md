# Документация WorkfloW

Вся проза проекта живёт здесь. В корне репозитория остаются только `README.md`
(обзор продукта и запуск) и `AGENTS.md` / `CLAUDE.md` (правила для ИИ-агентов,
`AGENTS.md` перезаписывается самим `next dev`).

## Структура

| Путь | Что внутри |
|---|---|
| [`audit/`](./audit) | Экспертный аудит продукта и план перехода «прототип → приложение» |
| [`tasks/`](./tasks/README.md) | Рабочая доска: аудит, разбитый на задачи по волнам, и инструкция по началу сессии |
| [`architecture/lock-system.md`](./architecture/lock-system.md) | Полный план системы блокировки: мастер-ключ, файловые ключи, redact-слой, инварианты 10.1–10.13 |
| [`architecture/secrets-vault.md`](./architecture/secrets-vault.md) | Менеджер секретов: что сделано, как устроено, честные ограничения модуля |
| [`product/original-brief.md`](./product/original-brief.md) | Исходное задание на модуль секретов (историческая справка) |
| [`product/secrets-vault-plan.md`](./product/secrets-vault-plan.md) | Черновой план модуля секретов |
| [`product/secrets-vault-inventory.md`](./product/secrets-vault-inventory.md) | Инвентаризация возможностей менеджеров паролей (сравнение с рынком) |
| [`product/secrets-vault-plan.pdf`](./product/secrets-vault-plan.pdf) | Тот же план в виде PDF на утверждение |

Рабочие артефакты вне `docs/`:

- `../memory/PRD.md` — живой продуктовый документ: что сделано, когда и что дальше.
- `../test_reports/iteration_*.json` — отчёты приёмки по итерациям
  (три последних в корне каталога, старые — в `../test_reports/archive/`).
- `../tests/api/test_ai_api.py` — интеграционные тесты серверных маршрутов `/ai-api/*`.
- `../ai/README.md` — описание файлового слоя ИИ (скиллы, MCP, сессии).

## Правила

1. Новый документ — в один из подкаталогов `docs/`, а не в корень.
2. Документ, который описывает уже реализованное решение, помечается как
   реализованный в первой строке, а не удаляется: он объясняет «почему так».
3. Переписка с агентами и промежуточные хендоверы в репозиторий не попадают.
