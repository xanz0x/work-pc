# WorkSpaceX для Windows: главный ПК и подключение друга

## Принятое решение

Главный ПК владельца — единственная база и единственный сервер ИИ. Друг устанавливает тот же файл, выбирает «Подключиться» и работает с этим сервером. **Не запускайте две копии Next поверх общей сетевой папки:** сервер держит часть состояния в памяти, поэтому нужен один процесс и один каталог данных.

Оба ПК имеют 8 ГБ ОЗУ. По умолчанию выбрана **Qwen2.5 3B Q4**, а не 7B: веса около 1,9 ГБ; движок загружается отдельно, около 1,5 ГБ. Требуется 12 ГБ свободного места для скачивания, распаковки, модели и базы. Производительность на ваших ПК ещё не измерена. Контекст 8192, одна параллельная генерация, одна загруженная модель. После 5 минут простоя веса могут освобождаться из RAM; сервис остаётся запущенным и загружает их при следующем запросе.

## Что делает владелец

1. Запускает `WorkSpaceX-Setup-1.0.0-x64.exe`, устанавливает программу в отдельную папку. Windows 10 **22H2** x64 или Windows 11 x64.
2. Выбирает **«Главный ПК»**. Вводит логин, пароль от 12 символов и повтор пароля. Это не мастер-ключ личного сейфа: тот настраивается отдельно внутри приложения.
3. Указывает постоянный IPv4-адрес или имя ПК в общей сети/VPN. Лучше закрепить адрес на роутере, чтобы ссылка друга не менялась.
4. Вводит `SONJJ_API_KEY` для SmailPro либо добавляет его позже через меню «Программа → Настройка и подключение». Без ключа Gmail/Outlook не выдаются. Существующий бесплатный генератор временной почты работает отдельно и тоже требует интернета.
5. Подтверждает условия **Qwen Research License** для 3B. Это не Apache 2.0; коммерческое использование требует отдельной проверки условий.
6. Программа создаёт новые ключи и чистую базу, запускает приложение, скачивает проверенный движок и модель, выполняет первый запуск модели. Прерывание загрузки допускает повтор. Движок не запускается до проверки SHA-256.
7. В разделе **«Администрирование»** создаёт друга. Для второго администратора выбирает роль **«Администратор»**. Временный пароль друг меняет при первом входе. Автоматически неизвестный второй аккаунт не создаётся — это последнее уточнение владельца.
8. Копирует приглашение из мастера и передаёт другу отдельно от пароля.

## Что делает друг

1. Устанавливает тот же `.exe`, выбирает **«Подключиться»**, вставляет приглашение `WSX1-…`.
2. Программа проверяет HTTPS-сертификат главного ПК по отпечатку, сроку и имени. Неверный сертификат не принимается.
3. Входит с учётной записью, которую создал владелец. Отдельные Node, Ollama, ключ SmailPro и база ему не нужны.

**Приглашение подключения и код общего диска — разные вещи.** Второй администратор видит общий диск автоматически; обычный пользователь получает доступ к диску по его штатному коду. Права, ограничения и личные сейфы сохранены.

## Интернет, сеть и доступность

- На главном ПК после скачивания модели локальный чат и локальное приложение не требуют интернета.
- Другу всегда нужна связь с главным ПК. В одной сети интернет для этого не нужен; из другой сети требуется заранее настроенная VPN/доступный частный маршрут. Приложение не создаёт VPN и не обходит NAT самостоятельно.
- При запросе Windows Firewall разрешите приложению доступ в **частной сети**. Публичный доступ и порты роутера автоматически не открываются. Если Windows не показала запрос, разрешите TCP-порт из `WSX_HTTPS_PORT` только в доверенной сети средствами Windows.
- При закрытом приложении, выключенном ПК или ручном переводе в сон друг не сможет работать. Пока сервер запущен, программа просит Windows не усыплять его автоматически. Меню завершения предупреждает об отключении друга.
- Внешняя почта, IMAP/SMTP, SmailPro и mail.tm требуют интернета. Облачный ИИ в этой установке не настроен; локальный режим никогда не подменяется внешним провайдером.

## Данные и окружение

Корень — `app.getPath('userData')`, обычно `%APPDATA%\WorkSpaceX`. Локальные профили браузера изолированы по адресу и сертификату сервера.

| Данные | Где и как |
|---|---|
| Пользователи, сессии, лицензии, чаты, общие метаданные | `data/`, только главный ПК |
| Байты общего диска | `data/cloud/objects/`, непрозрачные SHA-256 имена; доступ через существующие права API |
| Личные сейфы | IndexedDB/профиль встроенного браузера соответствующего пользователя |
| Модель | `models/`, только главный ПК |
| Проверенный движок | `runtime/<версия>/`, только процессы этой установки |
| Адрес и отпечаток сервера | `connection.json`, без паролей |
| Служебные секреты | `secrets.bin`, Electron safeStorage/Windows DPAPI; привязаны к учётной записи Windows |
| Сертификат HTTPS | `certificate.pem`, `private-key.pem`, не входит в приглашение/сборку |

Не переносите только `secrets.bin` на другую учётную запись Windows: DPAPI там его не расшифрует. Не заменяйте `MAIL_SECRET` для существующих ящиков. Удаление программы сохраняет данные и модель; ручное удаление профиля стирает их. Резервную копию главного ПК делайте после закрытия приложения; криптографический экспорт для переноса между Windows-профилями пока не реализован.

### Какие значения нужны для `.env`

**Вводите только:** логин администратора, его пароль, адрес главного ПК и при необходимости `SONJJ_API_KEY`. Друга создаёте штатной формой. Пароли в чат/исходники/установщик не нужны.

**Создаются автоматически:** `APP_SESSION_SECRET`, `MAIL_SECRET`; `APP_PASSWORD` и `ADMIN_LOGIN` — из формы. Эти значения хранятся зашифрованно и передаются дочернему серверу через окружение, а не открытым текстом в `.env`.

**Заданы в `desktop/runtime.env`:** `WSX_HTTPS_PORT=38631`, `WSX_NEXT_PORT=38632`, `WSX_LOOPBACK=127.0.0.1`, `WSX_LISTEN_HOST=0.0.0.0`, `OLLAMA_HOST=127.0.0.1:38633`, `OLLAMA_URL`, `OLLAMA_MODEL=qwen2.5:3b`, `OLLAMA_NUM_CTX=8192`, `OLLAMA_KEEP_ALIVE=5m`, `OLLAMA_NUM_PARALLEL=1`, `OLLAMA_MAX_LOADED_MODELS=1`, `CLOUD_STORAGE=local`, сроки сессии и лимиты запросов. `AI_DIR` и `OLLAMA_MODELS` вычисляются из профиля Windows. Созданный `.env.local` — снимок несекретных параметров для диагностики; меняйте параметры сборки до установки, не редактируйте адрес уже подключённого сервера вручную.

Не нужны для этой схемы: облачный LLM-ключ, MongoDB, внешнее объектное хранилище, Google OAuth, пароль базы. Почтовые IMAP/SMTP-учётные данные пользователь добавляет штатными формами, не в установщик.

## Сборка для разработчика

```
yarn install
yarn --cwd desktop install --frozen-lockfile
node desktop/scripts/build.mjs
```

Node 22.12+ для сборки; отдельная программа Node не нужна конечному пользователю. При Node 20 в окружении есть build-only `desktop/node_modules/node/bin/node`.

Сборка Next — `.next-desktop`, основной веб-сервер `.next` не заменяется. `desktop/staging/server` собирается по allowlist: ни `.data`, ни изменённые `ai/users`, `ai/mcp`, история, тестовые пароли или `.env` не копируются. System prompt для чистой установки — `desktop/assets/system.md`. Отчёт состава: `desktop/staging/payload-report.json`.

Результат: `desktop/release/WorkSpaceX-Setup-1.0.0-x64.exe`. NSIS-скрипт — `desktop/assets/installer.nsi`; удаление не затрагивает профиль данных. Также есть Windows job `.github/workflows/windows-installer.yml` для сборки на Windows. Это описание процесса, не утверждение, что job уже был запущен.

## Границы проверки

Сборка в Linux не заменяет запуск на реальных Windows 10/11: отдельно нужны проверка DPAPI, распаковки Windows Ollama, брандмауэра, производительности на 8 ГБ, установки/обновления/удаления. Без подписи издателя возможен SmartScreen. HTTPS-сертификат главного ПК не является цифровой подписью `.exe`.
