## 0. МИССИЯ

Реализуй в проекте `vault-core-arch` (Next.js 16 / React 19 / TS strict / Tailwind v4, браузерный local-first прототип WorkfloW) **модуль «Менеджер секретов»**: полноценный менеджер паролей и seed-фраз в боковой панели — профессиональный, защищённый, со всеми удобствами 2026 года (генераторы, TOTP, clipboard timeout 10 сек, авто-скрытие, Health, импорт/экспорт) — **в стилистике существующего dark-дизайна «Графит»** (зелёный акцент #2fbe7e, волосяные границы, без blur/теней).

**Ключевой принцип:** модуль строится ПОВЕРХ существующей криптосистемы замка (PBKDF2-HMAC-SHA256 310k → AES-GCM-256), а не рядом с ней. Никакой новой крипты не изобретать.

### 2.2 Модель данных (версия v1, миграции обязательны)

```ts
// lib/secrets/types.ts — формат vault-хранилища, ВСЕГДА с полем version
type SecretRecord = {
  id: string                 // 'sec-' + nanoid-подобный
  version: 1                 // ← для будущих миграций
  type: 'login'|'note'|'card'|'api'|'ssh'|'seed'|'wifi'|'license'|'identity'|'recovery'|'passkey-meta'|'custom'
  title: string
  folderId: string | null
  tags: string[]
  favorite: boolean
  fields: SecretField[]      // унифицированные поля (в т.ч. custom)
  totp?: TotpConfig | null
  attachments: Attachment[]  // ссылки на зашифрованные блобы
  icon?: { domain: string; b64: string } | null   // favicon в кэше сейфа
  createdAt: number; updatedAt: number
  history: HistoryEntry[]    // снапшоты секретных полей
  expiredAfter: number | null
  deletedAt: number | null   // мягкое удаление → корзина
}
type SecretField = {
  id: string; name: string; kind: 'text'|'password'|'url'|'email'|'number'|'date'|'secret'|'multiline'|'boolean'|'file'
  value: string              // секретные значения хранятся ct:iv (см. 2.3)
  secret: boolean            // маскировать в UI
}
type HistoryEntry = { at: number; fieldId: string; prevCt: string } // снапшоты секретов
```

Хранение: `localStorage['wf.secrets.v1']` через `usePersistedState` (паттерн vault-store), ключи с префиксом `wf.*` как у всех. Секретные значения полей — `ct:iv` (шифрование файловой схемой из use-file-keys). Папки: `wf.secrets.folders.v1`. Иконки: inline в записи (b64), загрузка при первом показе карточки.

### 2.3 Крипто (не изобретать, надстроить)

- **Корень доверия — существующий мастер-ключ** из `crypto-vault.ts` (PBKDF2 310k→AES-GCM-256). Если замок выключен — vault требует его включить (по образцу `security-section.tsx`, уже есть UI).
- **Записи шифруются файловой схемой** из `use-file-keys.ts` (`packSecret`/`ct:iv`), salt = SHA-256('wf.secrets.'+entryId) — точный аналог файловых ключей.
- **Итерации KDF: поднять 310k → 600k** (OWASP 2024) в миграции формата замка (v1→v2), со стабильной re-unwrap миграцией (старые verifier'ы перекодируются при первом успешном unlock).
- **2-й уровень для отдельных записей** (seed, карты): файловый ключ 2-го уровня (тот же механизм, что у файлов). Правило UX то же: файловый ключ не наследуется от мастер-ключа.
- **Миграции формата:** поле `version: 1`; любые будущие изменения схемы — через `migrateSecrets()`, как `migrateLockedNotes` в замке.

### 2.4 Интеграция с поиском и ИИ-чатом (жёстко)

- В `searchAll()` добавляется источник «secret» (HitKind `secret`), иконка — щит; **redact-правило: записи под файловым ключом ищутся только по title, sub='Под ключом'** (аналог `locked:true` у файлов).
- **Секреты никогда не попадают в контекст ИИ-чата** — ни в sources, ни в смысловой индекс, ни в экспорт разговора (расширить redact-фильтр из `screen-chat.tsx:252`).
- В глобальную палитру Ctrl+K секреты попадают автоматически через `searchAll` + `runHit` (ветка «открыть секрет»).

## 4. SECURITY REQUIREMENTS (из security-review)

1. **Local-first:** ни один секрет не покидает устройство. Ни одного fetch к внешним API с содержимым записей. Единственные сетевые вызовы — favicon (только домен) — тумблер в настройках.
2. **Минимизация plaintext:** секретные значения в UI по умолчанию маскированы; reveal с авто-скрытием 8с; copy без показа; nowhere plaintext в DOM дольше, чем показан.
3. **Буфер обмена:** автоочистка 10с (TOTP/CVV 5с), тост с обратным отсчётом, «Clear now»; честно в настройках: «ОС не гарантирует, что стороннее ПО не сохранит буфер».
4. **Память:** секретные строки обнулять после использования (по образцу `masterRef` = null в lockNow); React state с секретами не переживает lockNow (lockEpoch сброс).
5. **Анти-брутфорс:** наследуется от замка (failDelayMs 1→30s) — свой таймер не городить.
6. **Audit log:** события vault (создана/изменена/удалена запись, показ секрета, импорт/экспорт, смена ключа) → в общий журнал сейфа (замок уже пишет туда).
7. **CSP/заголовки:** не ослаблять. Скрипты только свои. Не добавлять `dangerouslySetInnerHTML` для контента записей (XSS через title/заметки). Markdown в secure notes — рендерить в React-элементы, не в HTML.
8. **Импорт:** валидация входа (zod-схемы CSV/JSON), ограничение размера файла (5МБ), лимит числа записей; не полагаться на структуру (whitelist полей).
9. **Экспорт plaintext:** красное предупреждение + ввод названия подтверждения + уведомление в журнал + подсказка про удаление файла руками (ОС не гарантирует secure delete).
10. **LocalStorage-миграции:** `wf.secrets.v1` с полем `version`; миграции идемпотентны, с бэкапом старого значения в `wf.secrets.backup.<ts>` перед изменением схемы.
11. **Иконки favicon:** только домен наружу; полученные изображения рендерятся из локального кэша (b64), не `<img src="https://...">` на лету (никаких утечек по referrer).
12. **Секреты в ИИ-чате:** расширить redact-context — секреты в списке источников заменяются на «Под ключом», из смыслового индекса исключаются. **Тумблер не даёт выключить эту защиту.** (Если реализация п.10.10 замка уже делает это — не дублировать.)

## 7. ПРИЁМКА (если не пройдено — не переходи к следующему шагу)

- **tsc:** `npx tsc --noEmit` → exit 0
- **Замок не сломан:** включение/выключение замка, unlock по PIN и по паролю, автоблокировка, Ctrl+Shift+L, файловые ключи на файле и на стикере — работают как до твоих правок

- **Redact:** запертая запись в поиске = только title + «Под ключом»; в чате секрет не появляется ни в источниках, ни в экспорте
- **Search:** секреты в топбаре и Ctrl+K; фильтры работают
- **Import:** CSV из KeePassXC → preview → импорт → количество совпало
- **Backup/restore:** круговорот бэкап→wipe→restore → данные совпадают
- **Reveal:** авто-скрытие через ~8с; при уходе со страницы скрывается
- **Favicon:** домен уходит наружу, кэш локальный, тумблер работает
- **Стиль:** живые скрины экрана vault, сайдбара, тостов — «Графит», без KeePass-клона
- **Edge cases:** пустой vault (онбординг), 1000+ записей (виртуализация списка не обязательна, но lag-ов нет), 2 вкладки (BroadcastChannel-синк: lockNow в одной → lock во второй; unlock не переносится), приватный режим (usePersistedState fallback), таймауты clipboard для каждого типа (login 10с / TOTP 5с / username 30с), истёкшая запись (EXPIRED бейдж), удаление в корзину → restore
