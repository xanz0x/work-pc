## NF-1 · Реальный индексатор файлов `P1` `DONE*`

**Сейчас.** «Добавить файл» создаёт только метаданные, содержимое не читается,
конвейер OCR — таймеры.

**Файлы.** новый `lib/indexer/*` + Web Worker · `lib/db/*` (из P0-3)
· `components/screen-library.tsx` · `lib/vault-store.tsx` (addFiles, reindexAll)

**Шаги.**
1. Выбор папки через File System Access API, сохранение handle с разрешением.
2. Worker-пайплайн: чтение → извлечение текста (txt/md/pdf) → чанки → ключевые слова →
   индекс. Тяжёлое не в главном потоке.
3. Хранить в IndexedDB: содержимое, чанки, индекс, хеш файла.
4. Инкрементальность: по хешу переиндексировать только изменённое.
5. Честный прогресс с отменой; статус «в обработке» из реального состояния, не по таймеру.
6. Поиск (`lib/search.ts`) начинает искать по содержимому, уважая redact-слой.

**Готово когда.** Папка на 1 000 файлов индексируется в фоне без блокировки UI,
поиск находит по тексту, повторный запуск обрабатывает только изменения.

**Статус — `DONE*` (код готов, ждёт ручной приёмки).**

_Сделано._
- Архитектура `lib/indexer/*`: `fs.ts` (выбор папки через File System Access API +
  сохранение handle, фолбэк `<input webkitdirectory>`), `worker.ts` (весь тяжёлый
  разбор в Web Worker), `pipeline.ts`, `extract.ts`, `chunk.ts`, `content.ts`,
  `store.ts`, `runner.ts`, `types.ts`, `context.tsx`.
- PDF без зависимостей: `pdf.ts` распаковывает `FlateDecode` штатным
  `DecompressionStream`; сканы без текстового слоя помечаются честно.
- Хранение в IndexedDB (`lib/db/*`): содержимое, чанки, индекс, хеш файла.
- Инкрементальность по SHA-256: неизменённые файлы пропускаются (`skipped`),
  переиндекс только по `force` или смене хеша.
- Честный прогресс с отменой (`runner.ts` → `cancel()`, фазы `scan/index/done/cancelled/error`).
- Поиск (`lib/search.ts`) ищет по содержимому и уважает redact-слой
  (`redactIds`, значения секретов в индекс не попадают).
- UI: `components/index-strip.tsx`; юнит-тесты `tests/unit/indexer.test.ts` — зелёные.

_Осталось проверить._
- Ручной прогон на реальной папке ~1 000 файлов: фоновая индексация без фризов UI,
  корректный процент/отмена.
- Проверить фолбэк `<input webkitdirectory>` в браузере без FSA (Firefox/Safari).
- Убедиться, что повторный запуск реально пропускает неизменённое (счётчик `skipped`).

**Проблема.** `lib/vault-store.tsx` — 1550 строк и один контекст; `setInterval(setNow, 1000)`
перерисовывает всё дерево раз в секунду.

**Файлы.** `lib/vault-store.tsx` → `lib/store/{clock,data,notifs,settings,lock}.tsx` · все экраны

**Шаги.**

2. Затем разрезать по доменам, сохранив внешний API `useVault()` как фасад
   (обратная совместимость важнее красоты).
3. Подписки через `useSyncExternalStore` + селекторы; производные (`graph`, `clusters`)
   считать вне рендера.
4. Проверять React Profiler'ом после каждого шага, а не в конце.

**Готово когда.** Тик секунды не вызывает ререндер экранов без времени; действие
перерисовывает только свою область.

**Статус — `DONE` 2026-08-31.**

_Сделано._
- Часы: `lib/store/clock.tsx` (`ClockProvider`, `useNow`, `useCoarseTick`) — секундный тик
  подписывают только показывающие время. Часы статус-бара переехали в отдельный компонент
  `components/ui/status-clock.tsx`: свой `setInterval` в `AppShell` убран, каркас больше
  не перерисовывается раз в секунду.
- Домены: `toast.tsx`, `settings.tsx`, `notifs.tsx`, **`data.tsx`** (корпус, стикеры,

  фасад по эффекту (п.10.4 сохранён).
- Производные вне рендера: граф считается отложенно (`setTimeout` 180 мс) и склеен по времени;
  состав живых стикеров — по грубому тику 5 с; `useSyncExternalStore` на содержимом индексатора.

_Цифры (шаг 4, автотест вместо ручного Profiler — `tests/unit/store-renders.test.tsx`)._
