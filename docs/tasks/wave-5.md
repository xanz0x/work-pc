## NF-9 · Телеметрия по согласию `P2` `DONE`

**Файлы.** новый `lib/telemetry.ts` · `components/screen-settings.tsx`

**Шаги.**
1. Локальная агрегация: счётчики событий без содержимого (какие экраны, какие действия,
   где обрывается сценарий).
2. Экран «что будет отправлено» с точным payload перед первой отправкой.
3. Отправка только по явному согласию; выключение стирает накопленное.

**Готово когда.** По умолчанию выключено, payload виден пользователю, отключение чистит данные.

**Статус — `DONE` 2026-06-03.**

_Сделано._
- `lib/telemetry.ts` — локальная агрегация на счётчиках. Главное решение:
  имена событий берутся из ЗАКРЫТОГО словаря (`TELEMETRY_SCREENS` /
  `TELEMETRY_ACTIONS` / `TELEMETRY_DROPS`), всё остальное `track` молча
  отбрасывает. Имя файла, текст запроса или id записи не могут попасть
  в телеметрию даже по ошибке разработчика — это проверяется юнит-тестом.
- Нет идентификатора устройства, сессии и пользователя: в payload нечему
  быть уникальным, поэтому «анонимно» — не обещание, а свойство данных.
- Что считается: открытия экранов; действия (`files.intake`, `files.reindex`,
  `search.run`, `chat.turn`, `lock.unlock`, `vault.entry.create`,
  `backup.export`, `demo.clear`); обрывы сценариев (`chat.turn.aborted`,
  `chat.turn.error`, `files.intake.failed`, `lock.unlock.failed`,
  `search.empty`).
- Экран «что будет отправлено» в Настройках → Приватность показывает НЕ пересказ,
  а сам объект: `JSON.stringify(payload)` — ровно то, что уйдёт. Рядом счётчики
  по трём осям, кнопки «Отправить сейчас» и «Очистить накопленное».
- Согласие: тумблер «Отправлять анонимную статистику» выключен по умолчанию;
  пока он выключен, кнопка отправки недоступна, а `sendTelemetry(consent)`
  требует согласие аргументом — отправку нельзя вызвать «между делом».
  Отзыв согласия стирает накопленное сразу, а не при следующем запуске.
- Приём: `POST /ai-api/telemetry/usage` пишет агрегат в `ai/telemetry/*.json`
  на том же диске (наружу не уходит ничего). Сервер принимает только известные
  ключи и только конечные неотрицательные числа: обещание проверяется
  на приёме, а не на слово. Маршрут закрыт сессией и лимитом частоты.
- Отправка обнуляет счётчики: одни и те же события не уезжают дважды.

_Проверено._ Юнит `tests/unit/telemetry.test.ts` (произвольное имя не считается,
payload — только числа и период, без согласия и на пустом агрегате отправки нет).
E2E `tests/e2e/20-telemetry-consent.spec.ts`: по умолчанию отправка недоступна,
payload виден и разбирается как JSON, после согласия отправка проходит и обнуляет
накопленное, отзыв согласия стирает данные. Файл агрегата проверен на диске.

## NF-10 · MCP-сервер наружу `P3` `DONE`

**Файлы.** новый `app/mcp/*` · `lib/journal.ts` · новый `lib/permissions.ts` ·
новый `lib/mcp-server.ts` · новый `lib/mcp-bridge.tsx` · `components/mcp-section.tsx`

**Шаги.**
1. Инструменты сервера: поиск, чтение метаданных, создание стикеров;
   запись секретов — только по отдельному разрешению.
2. Токены с областью видимости и сроком, отзыв токена.
3. Каждый вызов в журнал безопасности; опасные операции требуют подтверждения в UI.
4. Проверить сценарий из Claude/агента end-to-end.

**Готово когда.** Внешний агент выполняет разрешённые операции по токену, всё видно в журнале.

**Осторожно.** Это самая большая поверхность атаки в продукте: без волны 1 (auth) не начинать.

**Статус — `DONE` 2026-06-04.**

_Сделано._
- `POST /mcp` — MCP Streamable HTTP (JSON-RPC 2.0, без зависимостей):
  `initialize`, `ping`, `tools/list`, `tools/call`. Авторизация только
  Bearer-токеном `wsx_<id>_<secret>`; сессия браузера сюда не пускает.
  `tools/list` отдаёт лишь инструменты, разрешённые областями токена.
- `lib/permissions.ts` — области `search` / `read` / `notes:write` /
  `secrets:write`, соответствие инструмент → область, признак опасной операции.
  Инструменты: `search`, `list_files`, `get_metadata`, `create_sticker`,
  `create_secret`. Наружу не уходят значения секретов, тексты файлов и тела стикеров.
- Токены: имя, области, срок (1 ч / 24 ч / 7 д / 30 д), отзыв. На сервере
  хранится только SHA-256 хеш секрета (`AI_DIR/mcp-access/tokens.json`),
  значение показывается один раз. Лимит 60 вызовов/мин на токен.
- Мост: данные сейфа живут в IndexedDB браузера, поэтому сервер ставит
  задание в очередь, а открытая вкладка (`McpBridge`, long-poll
  `/mcp/admin/bridge`) выполняет его через те же сторы и возвращает ответ.
  Без вкладки агент получает `NO_BRIDGE`, а не пустой результат.
- Опасная операция (`create_secret`): первый вызов → `pending_approval` +
  `approvalId`; владелец в Настройки → «MCP наружу» видит запрос (без значений
  полей) и жмёт «Одобрить и выполнить» / «Отклонить»; агент повторяет вызов с
  `approvalId`. Запрос живёт 10 минут; чужой токен его не видит.
- Журнал: серверный аудит (`audit.jsonl`, append-only) доставляется во вкладку
  и ложится в журнал безопасности новыми типами `mcp-token-issued`,
  `mcp-token-revoked`, `mcp-call`, `mcp-denied`, `mcp-approval` — включая
  отказы по неверному/отозванному токену, которых вкладка сама не видела.
- Маршруты управления `/mcp/admin/*` закрыты сессией через `proxy.ts`.

_Проверено._ Юнит `tests/unit/mcp-access.test.ts` (области, формат токена,
выдача/отзыв/аудит, NO_BRIDGE, доставка задания, отказ в подтверждении).
API `tests/api/test_mcp.py` (12 проверок: 401 без токена, 405 на GET,
`tools/list` по областям, SCOPE_DENIED, pending → reject → REJECTED, отзыв).
E2E `tests/e2e/21-mcp-external.spec.ts`: агент по токену ищет по демо-корпусу,
создаёт стикер, секрет записывается только после одобрения в UI, всё в журнале,
отозванный токен получает 401.
