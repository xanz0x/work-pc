# Рабочая доска WorkfloW · план после утверждения аудита

Аудит утверждён владельцем продукта (июнь 2026). Источник решений —
[`docs/audit/WorkfloW-Audit-2026-06.pdf`](../audit/WorkfloW-Audit-2026-06.pdf).
Здесь то же самое, разбитое на задачи с короткими инструкциями «что делать».

## Как работать с доской

0. Первый раз в сессии — прочитать [HOW-TO-WORK.md](./HOW-TO-WORK.md) (40 секунд).
1. Открыть волну, взять первую задачу со статусом `TODO` — порядок внутри волны не менять.
2. Читать только блок задачи: в нём цель, файлы, шаги и критерий готовности. Аудит перечитывать не нужно.
3. Волну не смешивать: не начинать следующую, пока в текущей остались `TODO`.
4. После задачи: `npx tsc --noEmit` → прогон затронутого сценария → статус `DONE` + дата в этом файле.
5. Спорное место — брать самый консервативный вариант, сохраняющий текущее поведение. Продуктовую концепцию не менять.
6. Обновлять `memory/PRD.md` после каждой завершённой волны, а не после каждой задачи.
