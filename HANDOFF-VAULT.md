## 1. Как запустить и проверить (важно для этой среды)

```bash
cd /app
pnpm install                      # зависимости уже установлены
npx tsc --noEmit                  # ГЛАВНЫЙ гейт качества, сейчас exit 0
npx next build && npx next start -p 3000 -H 0.0.0.0    # preview-URL
```

- `next dev` в этой среде НЕ годится: Next 16 отдаёт чанки с 403 (cross-origin check),
  страница приходит без гидрации. Проверяем production-сборкой.
- После любого изменения кода нужен новый `next build` + перезапуск `next start`
  (`pkill -9 -f next` перед запуском, иначе EADDRINUSE и старый билд отдаёт 500 на новые чанки).
- Хосты preview добавлены в `allowedDevOrigins` в `next.config.mjs`.
- Мастер-ключ для тестов: метод «Пароль», `test-master-1234` (см. `memory/test_credentials.md`).
  Профиль браузера в автотестах чистый → замок создаётся заново в каждом сценарии.

## 2. Что сделано (CORE v1, шаги 2–16 §6 промта)

### Крипто-слой и замок
- `LOCK_ITERATIONS` поднят 310 000 → **600 000** (`lib/crypto-vault.ts`), добавлен
  `LEGACY_LOCK_ITERATIONS`, экспортированы `VERIFIER_TEXT`, `SALT_BYTES`, b64-хелперы.
- `lib/lock-migrate.ts`:
  - `migrateKdfIterations()` — ленивая миграция при первом успешном unlock:
    новый salt + 600k, пере-упаковка всех обёрток, бэкап старой схемы в
    `wf.lock.migrate.backup.<ts>`, уведомление в ленту.
  - `rewrapAll()` — переупаковка файловых ключей (`wf.vault.keys.*`), секретов
    locked-стикеров и ключа сейфа секретов под новый мастер-ключ.
  - Вызовы: в `unlock()` (миграция) и в `changeMaster()` (пере-упаковка — раньше
    смена мастера тихо ломала файловые ключи, теперь нет).
- `hooks/use-file-keys.ts`: добавлен `getMasterSession()`.
- `lib/secrets-crypto.ts`: SEK (32 случайных байта, завёрнут мастером,
  `wf.secrets.sek.v1`) → HKDF-SHA256 с salt `SHA-256('wf.secrets.'+entryId)` →
  AES-GCM-256 → значение поля как `ct:iv`. Плюс портируемые снимки
  (`sealPortable`/`openPortable`, PBKDF2 600k) и бэкапы под мастером.

### Модель и логика
- `lib/secrets.ts` — 12 типов записей, 9 видов полей, шаблоны, миграция формата
  (`migrateSecrets`), фильтры `type:/tag:/favorite:/expired:`, монограммы, домены.
- `lib/secrets-totp.ts` — RFC 6238/4226 на WebCrypto, Base32, `otpauth://`.
  **Сверено с официальными векторами RFC 6238: 6/6** (`scripts/totp-check.ts`).
- `lib/secrets-gen.ts` — генераторы (пароль/PIN/hex/UUID, произносимый режим) на
  `crypto.getRandomValues` без смещения по модулю; локальный strength-meter.
- `lib/secrets-io.ts` — импорт CSV (KeePassXC / Bitwarden / 1Password / LastPass) и
  Bitwarden JSON + наш plain-снимок; лимиты 5 МБ / 5000 записей, whitelist полей.
- `lib/secrets-store.tsx` — `SecretsProvider`/`useSecrets`: CRUD, папки, теги,
  избранное, корзина, история секретных полей, буфер обмена с автоочисткой,
  бэкапы с ротацией 5, favicon, Panic Lock+, публикация индекса в глобальный поиск.

### UI
- `components/screen-vault.tsx` — три колонки + шлюзы (`vault-gate-lock`,
  `vault-gate-wait`) + `ClipToast` с отсчётом и «Очистить сейчас».
- `components/vault/` — `vault-nav`, `vault-list`, `vault-detail`, `vault-editor`,
  `vault-generator`, `vault-io`, `secret-value` (reveal с авто-скрытием), `totp-cell`.
- `components/secrets-section.tsx` — секция настроек модуля (таймауты буфера по типам,
  секунды показа, favicons ВЫКЛ, авто-бэкап, «исключать секреты из ИИ» — включён и
  заблокирован от выключения).
- Каркас: `ScreenId 'vault'`, секция сайдбара «Секреты» (один пункт), `PLACEHOLDER`,
  `workspaceCount`, `statusText`, `page.tsx`, `HitKind 'secret'` в `lib/search.ts`,
  иконка/подпись в Ctrl+K, ветка `runHit`, `SECTIONS`/`FOCUS_ALIAS`/`SETTING_ENTRIES`.
  Дубль хоткея Ctrl+Shift+L в `app-shell.tsx` убран (остался один в `vault-store`).
- Стили — отдельный слой `/* ===== VAULT v1 ===== */` в конце `app/globals.css`
  (старое не рефакторилось), адаптив 3→2→1 колонки, `prefers-reduced-motion`.

### Приёмка, которая уже пройдена
`npx tsc --noEmit` = 0; создание/шифрование записи (в `wf.secrets.v1` нет plaintext);

и НЕ находит по значению; регрессия остальных экранов.

## 4. Честные ограничения, которые надо озвучивать пользователю
- Очистку буфера обмена выполняет браузер: историю буфера сторонних программ ОС
  отменить нельзя (написано в UI и в README).
- Иконки сайтов — единственный сетевой вызов, наружу уходит домен записи; тумблер по
  умолчанию выключен, картинка хранится в сейфе как b64 (внешних `src` в DOM нет).
- Восстановление из бэкапа заменяет живые записи снимком; корзина не трогается.
- Всё живёт в localStorage одного браузера: нет синхронизации и нет «забыли пароль».
