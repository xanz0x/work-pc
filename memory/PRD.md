## 2026-09-06 — Windows: главный ПК и подключение друга

### Исходная задача
«Твоя задача узнать все данные у меня что нужно для файла evn. 2 администра должно быть! Так же продумать логику установики что бы скачивалась модель ии и запускатьлась вместе с приложением что бы локальная модель всегда была доступна! Продумай вс так что бы в итоге у меня просто был установочиный файл и я могу уже пользоваться программой так же как и мой друг!»

Ответы: изучить имеющийся репозиторий; оба Windows10/11, по8ГБ RAM, GPU неизвестны. «Мой пк это единая база!» Друг работает, пока главный ПК включён. Последнее уточнение: «я сам создам пользователя», поэтому второй администратор создаётся владельцем штатной формой, без скрытого готового аккаунта. Desktop-данные чистые; прежние `/app/.data` и `/app/ai` не удалять и не паковать. SmailPro нужен, ключ вводится локально при настройке. Первый запуск с интернетом допустим.

### Реализованная архитектура
- Один Electron44/NSIS установщик x64 для владельца и друга. Владелец запускает единственный Next standalone и Ollama; друг — тонкий HTTPS-клиент. Не используется совместный файловый доступ SMB с двумя Next-процессами.
- Локальный мастер: логин/пароль владельца, адрес, SmailPro, согласие Qwen Research License. Служебные секреты создаются криптографически, сохраняются через safeStorage/Windows DPAPI, передаются дочернему серверу через environment. Никаких фиксированных паролей в installer.
- Приглашение: адрес + SHA256 сертификата, без пароля. Проверяются pin, hostname, сроки. Remote renderer sandbox/contextIsolation, без Node/preload. IPC только из главного фрейма локального мастера.
- HTTPS38631 → loopback Next38632; Ollama только127.0.0.1:38633. Настройки из `desktop/runtime.env`. Хранение в профиле Windows. Объекты общего диска локально в `AI_DIR/cloud/objects`, непрозрачные имена, прежние ACL. `CLOUD_STORAGE=local` не требует внешнего storage-провайдера.
- Qwen2.5 3B Q4 для8ГБ, около1.9ГБ + движок1.47ГБ, требуется12ГБ диска; num_ctx8192, одна генерация, keep_alive5m. Сервис остаётся запущенным; веса могут выгружаться после простоя. О скорости на8ГБ пока утверждений нет.
- Windows zip Ollama v0.33.3 закреплён SHA256/URL/размером (повторно сверены с официальной GitHub metadata). Возобновляемая загрузка, проверка до запуска, прогресс pull, warmup. Watchdog с лимитом рестартов, остановка только своих процессов, временный запрет автосна Windows.
- Native Ollama history теперь object arguments/tool_name; ошибки и обрывы NDJSON обрабатываются. 3B не считается установленной7B; возвращается реальный тег. Локальный ИИ не переключается в облако.
- Desktop не заполняется демо-сейфами. Чистый system prompt из `desktop/assets/system.md`, а не изменённых пользовательских AI-файлов.
- Раздельные сборки `.next-desktop` / `.next`. Allowlist payload; ASAR проверен:792 файла, приватные пути отсутствуют. NSIS сохраняет данные при удалении. Windows CI job добавлен, но здесь не запускался.
- Исправлен найденный edge API: неверный неполный features PATCH теперь400 вместо молчаливого игнорирования; старый тест учитывает mail/cloud.
