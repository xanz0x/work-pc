# PRD · WorkfloW · Менеджер секретов (модуль VAULT)

## Исходная задача
`02-prompt-claude-opus.md`: реализовать в существующем прототипе `vault-core-arch`
(Next.js 16 / React 19 / TS strict / Tailwind v4, local-first, дизайн «Графит») модуль
«Менеджер секретов» — менеджер паролей, TOTP и seed-фраз ПОВЕРХ существующей
криптосистемы замка (PBKDF2 → AES-GCM), не ломая ничего существующего.

## Решения владельца (сессия 2026-06, ask_human)
1. Объём: только CORE v1 (шаги 2–16 §6 промта).
2. KDF 310 000 → 600 000 разрешено, с ленивой ре-миграцией при первом unlock.
3. Zero-dependency — закон (ни одной новой npm-зависимости не добавлено).
4. Иконки сайтов через `google.com/s2/favicons` — реализовано, но тумблер по умолчанию ВЫКЛЮЧЕН
   (рекомендация агента: иначе домены записей утекают в Google).
5. Проверка — на preview-URL этой среды (порт 3000, `next build && next start`).

## Архитектура (что где лежит)
- `lib/secrets.ts` — модель, шаблоны 12 типов, фильтры `type:/tag:/favorite:/expired:`, миграция формата.
- `lib/secrets-crypto.ts` — SEK (32B, завёрнут мастер-ключом) → HKDF на запись → AES-GCM `ct:iv`;
  портируемые снимки (PBKDF2 600k) и бэкапы под мастер-ключом.
- `lib/secrets-totp.ts` — RFC 6238/4226 на WebCrypto, Base32, `otpauth://`.
- `lib/secrets-gen.ts` — CSPRNG-генераторы, локальный strength-meter.
- `lib/secrets-io.ts` — CSV/Bitwarden JSON импорт (валидация, лимиты), экспорт.
- `lib/secrets-store.tsx` — `SecretsProvider`/`useSecrets`: CRUD, папки, корзина, история,
  буфер с автоочисткой, бэкапы, favicon, panic-lock.
- `lib/lock-migrate.ts` — KDF 310k→600k + `rewrapAll` (файловые ключи, секреты стикеров, SEK).
- `components/screen-vault.tsx` + `components/vault/*` — экран из трёх колонок.
- `components/secrets-section.tsx` — секция настроек модуля.
- Слой стилей `/* ===== VAULT v1 ===== */` в конце `app/globals.css`.
- Точки правки каркаса: `ScreenId 'vault'`, `PLACEHOLDER`, `workspaceCount`, `statusText`,
  `page.tsx`, `HitKind 'secret'`, `HIT_ICON/KIND_LABEL`, ветка `runHit`, `SECTIONS`/`FOCUS_ALIAS`/`SETTING_ENTRIES`.

## Что сделано (2026-06, CORE v1)
- Крипто-слой поверх замка, KDF поднят до 600k с ленивой миграцией и бэкапом старой схемы.
- Смена мастер-ключа теперь честно пере-упаковывает файловые ключи и секреты стикеров (был пробел).
- Экран «Менеджер секретов»: навигация/список/деталь, 12 типов, конструктор полей,
  папки, теги, избранное, корзина с восстановлением и безвозвратным удалением.
- Генератор (пароль/PIN/hex/UUID) + strength-meter; TOTP с отсчётом и импортом otpauth.
- Буфер обмена с автоочисткой по типам, тост с отсчётом, «Очистить сейчас».
- Показ секрета с авто-скрытием, гашение при уходе со страницы/блокировке.
- Импорт CSV (KeePassXC и др.) и Bitwarden JSON с превью; экспорт зашифрованный и plaintext
  с подтверждением; бэкапы под мастер-ключом с ротацией и restore.
- Секреты в глобальном поиске и Ctrl+K как вид `secret` (только название/тип/теги).
- Panic Lock+ (Ctrl+Shift+L): замок + очистка буфера + гашение раскрытий; дубль хоткея убран.
- Секция настроек модуля; тумблер изоляции от ИИ включён и заблокирован.

## Приёмка (выполнено)
- `npx tsc --noEmit` → exit 0.
- TOTP сверен с официальными векторами RFC 6238 (`node scripts/totp-check.ts` после компиляции) — 6/6.
- E2E на preview: создание записи → шифрование → показ → копирование (буфер прочитан из браузера:
  значение появилось, после Ctrl+Shift+L буфер пуст) → корзина → восстановление.
- Импорт KeePassXC CSV: превью 3 записи (1 с TOTP) → импорт 3 → авто-создание папок Root/Work, Root/Crypto.
- Бэкап → restore → «Восстановлено 3 записей»; зашифрованный экспорт скачивается.
- F5 → экран блокировки → unlock → секреты снова расшифровываются.
- Смена мастер-ключа → секрет по-прежнему расшифровывается (путь `rewrapAll`).

## Как запускать в этой среде
```
npx next build && npx next start -p 3000 -H 0.0.0.0     # preview-URL
npx tsc --noEmit                                        # главный гейт
```
`next dev` в этой среде отдаёт чанки с 403 из-за проверки cross-origin у Next 16 —
для проверки используется production-сборка. Хосты preview добавлены в `allowedDevOrigins`.

## Сессия «VAULT v1.2» (июнь 2026) — favicon-фикс + 4 фичи, приёмка iteration_3 (4/5) + ручная доводка favicon → всё зелёное

## Сессия «VAULT v1.5» (июнь 2026) — 4 фичи P1, приёмка iteration_5: 100% PASS, замечаний нет
1. **Wi-Fi QR**: собственный кодер QR (`lib/qr.ts`, zero-dependency) — модель 2, байтовый режим UTF-8,
   уровень M, версии 1–10 (до 213 байт): GF(256), Рида-Соломона, чередование блоков, выбор маски
   по 4 правилам штрафов, format/version info. Проверен независимым декодером (OpenCV QRCodeDetector)
   на версиях 1–10 и на кириллице. UI: кнопка `detail-wifi-qr` только у записей типа Wi-Fi →
   модалка `wifi-qr-modal` (SVG-модули, автозакрытие 45 с, перерисовка, закрытие по panic-lock).
   Секрет в разметку не попадает — только модули (проверено тест-агентом).
2. **Generator Hub**: к 5 режимам добавлены «Фраза» (passphrase из словаря BIP39, 3–10 слов,
   разделитель через VtSelect, заглавные, число; энтропия считается как n·log2(2048)) и
   «Имя» (произносимые пары слогов, 2–4 блока, точка, цифры).
3. **Вид «Истекающие»**: пункт `vault-view-expiring` рядом со «Здоровьем паролей», счётчик
   с предупреждающим цветом; группы «Просрочено» / «Скоро истекут» (≤30 дн) / «С запасом»,
   бейджи EXPIRED и «N дн», сортировка по сроку, клик ведёт к записи. Расшифровки нет —
   только метаданные (`expiryStage`/`expiringCount` в `lib/secrets.ts`).
4. **Вложения**: `addAttachment`/`removeAttachment`/`downloadAttachment` в store — файл шифруется
   AES-GCM ключом записи (mime|base64 через `sealField`), лимит 256 КБ на файл и 1 МБ на запись;
   скачивание — расшифровка в память → Blob → отзываемый object URL. UI: `vault-attachments.tsx`
   в детали записи. Подтверждено: маркер из файла в localStorage отсутствует.
