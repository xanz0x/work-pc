## 🔴 Что осталось сделать (приоритеты)

### P0 — БЛОКЕР: починить production-сборку Next.js
Команда `pnpm run build` падает по двум причинам:

1. **ESLint plugin отсутствует**: ошибка `react-hooks/purity` — плагин не установлен или неправильно подключён.
   - Проверить `/app/package.json` и конфиг ESLint (`.eslintrc*` или `eslint.config.*`).
   - Возможные решения:
     - установить недостающий плагин: `pnpm add -D eslint-plugin-react-hooks`
     - либо отключить правило `react-hooks/purity` в конфиге, если оно не нужно
     - либо временно `eslint: { ignoreDuringBuilds: true }` в `next.config.js` (нежелательно, только как крайний вариант).

2. **Warning в `/app/instrumentation.ts`**: `Dynamic filesystem access causes tracing of the whole project`.
   - Убрать динамические `fs`/`path` вызовы с переменными путями.
   - Использовать статические импорты или вынести файловую логику в отдельный API route, вызываемый по требованию.
   - Цель — чтобы Next.js мог статически трассировать зависимости.

**Проверка:** после фиксов запустить:
```bash
cd /app && pnpm run build
```
Билд должен пройти без ошибок. Затем `sudo supervisorctl restart frontend` и убедиться, что фронтенд поднимается.

## Важные напоминания

- **Не пытайся запускать локальные LLM модели** — эта функциональность удалена по требованию пользователя.
- **Пакетный менеджер — `pnpm`**, не npm и не yarn (проект настроен под pnpm).
- **Supervisor управляет фронтом и бэком** — не запускай `next dev` вручную, используй `sudo supervisorctl restart frontend`.
- **Все API-роуты Next.js — под `/ai-api/...`** (не `/api/...`), это особенность этого проекта.
- **OpenRouter/Custom требуют ключей от пользователя** — ключи хранятся в настройках приложения, не в `.env`.
- **Emergent LLM key НЕ используется в этом проекте** — пользователь настаивает на своих ключах OpenRouter/Custom.
