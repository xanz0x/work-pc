## Философия

**WorkfloW** — это не «ещё один Notion». Это локальный сейф с ИИ, где приватность — не галочка в настройках, а фундамент:

- **Локально** — файлы, индекс, разговоры и ключи никогда не покидают устройство.
- **Красиво** — строгая дизайн-система «Графит»: глубина слоями тона, ни одного blur/тени.
- **Живо** — интерфейс отвечает на каждое действие: числа докручиваются, узлы дышат, плитки летают.
- **Безопасно** — настоящая криптография WebCrypto (PBKDF2 310k + AES-GCM), а не декоративные бейджи.

Продукт позиционируется в нише между Obsidian (локальность, платные сервисы) и AnythingLLM (локальный RAG-чат), добавляя то, чего нет ни у кого: **живую карту памяти + MCP-управляемость**.

```bash

npm i -g pnpm                 # если pnpm ещё нет

pnpm install                  # установка зависимостей
pnpm dev                      # dev-сервер → http://localhost:3000
```

> В этом рабочем каталоге сервер запускается на `127.0.0.1:3457` (см. «Разработка»).

Сборка продакшена:

Первый запуск показывает **библиотеку с демо-данными** (13 файлов, стикеры, разговоры) — это позволяет оценить все сценарии без своих файлов. Демо можно стереть кнопкой в Настройках → «Опасная зона».

## Четыре экрана

### 📚 Библиотека

Два слоя памяти: **файлы, которые пришли** — и **стикеры, которые вы подумали**.

- Загрузка файлов → конвейер: OCR → автотеги → ИИ-описание → индексация.
- **Доска плиток** (drag & drop): мозаика с размерами `sm/wide/tall/xl`, закрепление наверх, перетаскивание файлов в кластер-чип, полная клавиатурная альтернатива (Space → стрелки → Space, Escape-отмена), aria-live-анонсы.
- Кластеры-фильтры, семантический поиск, инспектор объекта справа (превью, метаданные, ИИ-описание, прикреплённые стикеры, связанные объекты).
- Стикеры: временные (с таймером распада) и постоянные, могут быть заперты на пароль.

### 🗺 Карта памяти

Живая нейрографическая карта: узлы-файлы, связи по смыслу, ядро **WORKFLOW CORE** в центре.

- Зум к области под курсором, отдаление возвращает ядро в центр.
- Клик по узлу → инспектор; поиск подсвечивает найденное акцентной кромкой с бегущим лучом.
- Метрики (связи, кластеры) анимируются; легенда кластеров внизу.

### 💬 Чат с ИИ

Разговор поверх собственного хранилища.

- Retrieval-trace: каждый ответ показывает, **из каких источников** он собран.
- Композер с рельс-подсказками, источник под курсором приподнимается, знак модели дышит при генерации.
- Локальный движок (Qwen 2.5 7B) или облачный — переключается в Настройках.
- Объекты под файловым ключом исключаются из контекста: ИИ физически не может процитировать защищённое.

### ⚙️ Настройки

Конвейер обработки (OCR, автотеги, слежение за папками), движок и модель, приватность (маскирование, телеметрия), уведомления, хранилище, опасная зона — и **секция «Безопасность»** (см. ниже).

## Система блокировки 安全

Полноценная двухуровневая защита, реализованная по плану [`LOCK-FEATURE-PLAN.md`](./LOCK-FEATURE-PLAN.md).

### Уровень A — мастер-ключ

| Возможность | Как |
|---|---|
| PIN **ровно 6 цифр** или пароль ≥ 8 символов | Настройки → Безопасность → «Настроить мастер-ключ» |
| Экран блокировки | Полноэкранная сцена «хранилище»: сетка-пол в перспективе, метеоры, PIN-ячейки с кареткой |
| Кнопка-замок | У шестерёнки в топбаре + хоткей **Ctrl+Shift+L** |
| Автоблокировка простоя | Никогда / 5 / 10 / 15 / 30 минут (тик 5 с, активность = click/keydown/pointermove) |
| Анти-брутфорс | Счётчик неудач → задержка 1s→2s→4s…, busy-флаг на время деривации PBKDF2 |
| Смена мастера | Полный re-setup с подтверждением старого; сессия остаётся разблокированной |
| Синхронизация вкладок | BroadcastChannel `workflow-lock`: закрыл в одной — закрылось везде |
| SSR-безопасность | Inline-bootstrap в `<head>` ставит класс `lock-pending` до гидратации — первый кадр не мигает |

### Уровень B — файловые ключи

- Любой файл или стикер можно **«Поставить на ключ»** — повторный ввод при каждом открытии, поверх мастер-разблокировки.
- Хранение: `wrappedFileKey = AES-GCM(masterKey, fileKey)` — при **смене мастера файловые ключи пере-упаковываются автоматически** (пере-wrap без знания старых паролей).
- **Redact-слой**: защищённые объекты вырезаются из поиска (`search.ts redactIds`), retrieval-trace чата, подсказок и инспекторов — вместо содержимого честная строка «Под ключом».
- Инвариант целостности (аудит при старте): `locked ⇒ шифртекст существует`, иначе блокировка честно снимается с событием в ленту.
- **Забыл мастер** → сброс стирает замок и все файловые ключи (файлы остаются) — предупреждение при создании.

### Криптография

```
PBKDF2-HMAC-SHA256, 310 000 итераций, salt 16B  →  AES-GCM-256
```

Нативный WebCrypto, ноль зависимостей. Деривация ≈ 104 мс на среднем железе. Секреты хранятся как `ct:iv` (base64) — в localStorage нет ни одного plaintext-пароля.

## Архитектура

```
┌─────────────────────────────────────────────────────────┐
│ app/layout.tsx                                          │
│  ├─ bootstrap-скрипт замка (синхронно, до гидратации)    │
│  ├─ RedactedProvider  ←-- реестр защищённых объектов     │
│  └─ VaultProvider      ←-- единое состояние приложения   │
└─────────────────────────────────────────────────────────┘
          │                                  │
   ┌──────▼──────┐                    ┌──────▼──────┐
   │ app-shell   │  lock-состояние,   │  4 экрана   │
   │ (каркас)    │  Ctrl+Shift+L,     │ library/map │
   │             │  storage-синк      │ chat/settings│
   └─────────────┘                    └─────────────┘

lib/crypto-vault.ts   PBKDF2+AES-GCM ядро (zero-deps)
lib/lock-store.ts     синхронный bootstrap, конфиг, аудит инвариантов
lib/redact-context    что скрыто в этой вкладке (locked \ unlocked)
hooks/use-file-keys   сессионный мастер, wrapped-ключи, миграция 10.6
hooks/use-board-dnd   жесты доски: Pointer Events, автоскролл, клавиатура
lib/board-layout.ts   чистая модель мозаики (тестируется в Node)
```

**Принципы:**

- **Единый сейф** — все экраны читают одно состояние (`useVault`); числа нигде не расходятся.
- **Чистые слои доски** — модель (`board-layout`) без React/DOM, жесты (`use-board-dnd`) без состояния, вид (`library-board`) — контролируемый.
- **Синхронный bootstrap замка** — статус читается до первого рендера; заглушка `lock-pending` не даёт «мигнуть открытым».
- **Unlock-факт живёт в памяти вкладки** (не в localStorage) — новая вкладка = новый ввод пина.
- **Кастомный Next.js 16** — см. `AGENTS.md`: API могут отличаться от известных, перед незнакомым кодом читать `node_modules/next/dist/docs/`.

| **LOCK v3.2** | Экран блокировки, кнопка-замок, секция «Безопасность», bootstrap-заглушка |
| **FILE-KEYS v3.2b** | Бейджи «под ключом», модалки файловых ключей |

| **POLISH v3.3** | `make-interfaces-feel-better`: концентрические радиусы, ghost-кнопки, акцентная заливка CTA, табличные числа |
| **INPUT-COUNT v3.4** | Живые счётчики длины, PIN-линейки, каретка ячейки |
| **LOCKSCREEN v3.5** | Сцена «хранилище»: retro-grid пол в перспективе, усиленные метеоры, 2-зонная карточка, гравировка |
| **v3.6–v3.7** | Фиксы читаемости монограммы, CTA, производительность (GPU-композит вместо repaint) |
| **INPUT v4.0 / CLUSTERS v4.1 / SIDEBAR v4.2** | Широкие настройки, просторные поля, свёрнутые кластеры, иконки секций без капса |
| **RESPONSIVE v3.8** | Полная адаптивность (см. ниже) |

**Законы системы:**

1. Глубина — **тонами и волосяными границами**. Запрещены blur, box-shadow, полупрозрачные пятна.
2. Один акцент `#2fbe7e` — только для активных состояний и интерактива.
3. Радиусы 3–4px (концентричность: внешний = внутренний + padding).
4. Числа — всегда `tabular-nums` (`.num`).
5. `transition-property` указывается точечно — никогда `all`.
6. Анимации уважают `prefers-reduced-motion` (глобальный блок глушит всё).
7. Справочные паттерны Magic UI берутся curl'ом (`https://magicui.design/r/<имя>.json`) и портируются вручную без зависимости `motion`.

## Адаптивность

Единая сетка брейкпоинтов (детали — блок `RESPONSIVE v3.8` в конце globals.css):

| Ширина | Поведение |
|---|---|
| ≥ 1280 | Полный расклад: сайдбар 248px + контент + инспекторы |
| ≤ 1280 | Инспектор библиотеки 320 → 280px |
| ≤ 1180 | Стол источников чата → фиксированное наложение |
| ≤ 1100 | Карта: компактный HUD; **чат: рельс → выдвижной ящик**; инспектор библиотеки под контентом |
| ≤ 1024 | Карточки в 2 колонки |
| ≤ 768 | Сайдбар → иконочная колонка 56px; чипы-фильтры — горизонтальный скролл; легенда карты — строкой |
| ≤ 520 | Экран блокировки: компактная типографика |
| ≤ 480 | Сайдбар → **нижняя таб-панель**; модалки `100vw − 24px` |
| ≤ 380 | Замок: статус-строка SESSION ⟷ ПОПЫТКИ; PIN-ячейки flex |
| `hover: none` | Тач: тап-зоны ≥ 44px, hover-состояния → always-visible |

Производительность анимаций: сетка-пол и метеоры работают на GPU (transform-only, фиксированный расклад без `Math.random` в рендере); на слабых машинах (`update: slow`) декоративные анимации отключаются.

## Данные и хранение

Всё состояние — `localStorage` с префиксами:

| Ключ | Содержимое |
|---|---|
| `wf.files.v1` | корпус файлов |
| `wf.notes.v1` | стикеры (секреты — `ct:iv` при активном замке) |
| `wf.chat.v1` | разговоры |
| `wf.notifs.v1` | лента событий |
| `wf.settings.v1` | конфигурация конвейера |
| `wf.lock.config` | замок: включён, метод, автоблокировка |
| `wf.lock.state` | salt + verifier + счётчик неудач |
| `wf.vault.keys.<id>` | wrapped-ключи файлов (`ct:iv`) |
| `wf.vault.keys.migrated` | маркер одноразовой миграции стикеров |
| `wf.filekeys.lockedlist` | список id под ключом (для redact между вкладками) |

**Не хранится никогда:** мастер-ключ, пароли файлов, факт разблокировки (только память вкладки).

Стирание: Настройки → «Опасная зона» → полный wipe сейфа.

## Безопасность: честные границы

Система защищает **от чужих глаз и рук** — коллеги за твоим ноутбуком, 家庭 гости, случайный показ экрана. Она **не защищает** от:

- форензики диска (localStorage читается DevTools владельца машины);
- вредоносных расширений браузера;
- физического изъятия устройства.

Формулировка в UI это отражает: «Ключи хранятся только на этом устройстве».

Следующие ступени (за пределами текущего прототипа): IndexedDB + non-extractable CryptoKey, шифрование самого корпуса файлов, синхронизация E2EE между устройствами.

## Разработка

```bash
pnpm dev --port 3457        # привычный порт этого каталога
pnpm dev                    # стандартный 3000
npx tsc --noEmit            # строгая проверка типов (должна быть чистой)
pnpm build                  # продакшен-сборка
```

**Практики репозитория:**

- `pnpm-workspace.yaml` держит `minimumReleaseAge: 0` — требует pnpm ≥ 9.
- `next.config.mjs` содержит `allowedDevOrigins: ['127.0.0.1','localhost']` — без него Next 16 блокирует отдачу dev-чанков (страница выглядит «мёртвой»).
- После любых правок: `tsc --noEmit` + проверка `HTTP 200`.
- Эмпирические тесты доски: `node --experimental-strip-types` по сценариям из `react-draggable-boards`.

**Работа с ИИ-агентами** — `AGENTS.md` (авто-подхватывается) и `CLAUDE.md` (→ AGENTS.md): кастомный Next 16 требует чтения встроенных доков перед кодом.
